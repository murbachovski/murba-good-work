# 0001 초기 결정 로그

- 날짜: 2026-11-24
- 상태: 확정 (변경 시 새 ADR로 대체하고 이 파일을 가리킨다)
- 맥락: 빈 폴더에서 플러그인 설계 시작. grill 질문 라운드 9회, 조사 15건(플러그인·문서 4, 독립 재검토 7, 논문·실무 3, 스킬 검색 1) 후 확정
- 근거 자료: [플러그인·실무 조사](../research/plugin-survey.md), [논문](../research/papers.md), 상세 설계는 [기획서 v0.1](../spec/spec-v0.1.md)

이 파일은 여러 결정을 한 번에 모은 **결정 로그**다. 나중에 논쟁이 생기는 결정(자동 머지, 메인 세션 오케스트레이터, eval 게이트 등)은 개별 ADR로 분리한다.

## 결정 표 (출처: 사 = 사용자 선택, 근 = 근거 기반 제안·사용자 확인, 제 = 제안)
| 항목 | 결정 | 출처 |
|---|---|---|
| 범위·배포 | 개인용 로컬 → 나중 GitHub 공개. 루트 = marketplace + CLAUDE.md + docs, 본체 `plugins/murba-good-work/`. 파일명 영문 소문자-하이픈 | 사/근 |
| 사람 접점 | ① 1단계 grill(선택형) ② **기획서 1회 승인**(기획서 + AC→테스트 대응표 + 검증 방법) — 이후 완전 자동 ③ 결정 큐 일괄 질문(비차단) | 사 |
| 0단계 작업 설계 | triage 에이전트가 `run-plan.json` 작성: 작업 유형별 절차(기능·버그·조사·리팩터·성능·프로토타입), 단계별 깊이, 투입 에이전트, 생략은 사유 필수, 예산, 버전 | 사 |
| grill | 전제 검증 → 대안 2~3 + 추천 → 실패 지도 → 핵심 5줄(왜·누가·위험·성공·범위) → 수용 기준(AC) ID 부여. 실행해서 알 수 있는 건 질문 대신 시험. 질문 일괄 방식(batch-grill-me 개작) | 사/근 |
| 결정 큐 | 3분류: 기계적(자동) / 취향(추천안 적용·보고) / 사용자 방향 변경(자동 금지). 추가 전용 원장. 최종 보고에 "내가 내린 결정과 틀렸을 때 비용" 전부 | 사/근 |
| 비가역 작업 | PreToolUse **차단(deny) + 사유 + 결정 큐 기록**. 그 갈래만 정지, 나머지 계속. `permissions.deny` 병행 | 근 |
| 오케스트레이션 | 메인 세션 = 오케스트레이터. **상태 전이표를 데이터 파일로 두고 hook이 강제**(StateFlow 근거). 단계마다 `handoff/<단계>.md`, 컨텍스트 40~60% 유지 | 사/근 |
| 에이전트 | triage(sonnet), spec-reviewer(opus, 읽기 전용, 1회), **test-writer(opus, AC만 보고 테스트 먼저 작성)**, builder(sonnet, 1회 실행 = AC 1개, 3라운드는 opus 새 builder), evaluator(opus, 수정 금지), pr-reviewer(opus), evolve-researcher(sonnet). 하위 에이전트 생성은 `tools`에서 Agent 제거로 강제. 추가·제거 절차를 기획서에 명시 | 사/근 |
| 역할 스킬 | 프론트·백엔드·AI·디자인은 builder가 로드하는 스킬(에이전트 `skills:` 미리 로드) | 근 |
| 병렬 | 구현은 builder 1개 순차. 독립 산출물 병렬은 **기본 꺼짐**, 자체 eval 근거 생기면 켬. 조사·리뷰는 병렬 | 사 |
| 커밋 | 대상 프로젝트: `feat/*`에 작업별 자동 커밋, main 직접 금지. 이 저장소: 지시 때만 | 사 |
| 수정 루프 | **최대 3라운드**(1~2 같은 builder, 3 상위 모델 새 builder), 2회 연속 개선 없음 → 중단, 같은 전제 2회 실패 → 전제 검증. 마지막 통과 SHA 보관·회귀 시 복원. 입력은 실행 결과만(자기 검토 금지) | 사/근 |
| Stop 게이트 | 단계당 3회·실행당 12회. 판정은 증거·handoff 파일 존재 같은 측정 조건만. 질문형 종료는 차단 대신 결정 큐 + 경고. 백그라운드 작업 중이면 보류. 내장 상한(연속 8회)·`/goal`과의 관계 명시 | 사/근 |
| 예산 | 경과 시간·서브에이전트 수·재시도 수 상한. 초과 시 통과 증거 먼저 저장 후 멈춤 보고. 토큰은 측정 수단 확인 후 | 사 |
| 테스트 신뢰 | test-writer 분리, 뮤테이션 검사로 테스트가 실제 잡는지 증명, AC·테스트 해시 고정, **evaluator만 아는 숨긴 검사**, builder에겐 실패 AC ID만 전달, 러너 설정·conftest·test 스크립트 쓰기 금지, 결정적 diff 규칙으로 조작 감지(LLM 감시는 보조) | 근 |
| 결정적 센서 | 5단계 셋팅이 대상 프로젝트에 타입체크·린터·구조 테스트 생성(오류 메시지에 수정 지침), 1회 실행으로 증명. 빠른 건 편집 직후, 비싼 건 8단계 | 근 |
| 브라우저 검증 | AC별 `@playwright/test`(종료 코드 = 증거) + 스크린샷. 콘솔 error·4xx/5xx = 실패, 건너뜀·브라우저 불가 = 실패, 재시도 통과 = ⚠️. 증거 덮어쓰기 금지, 비밀 마스킹, trace는 실패 시만. 프로젝트 전용 verify 스킬 생성. 상위 목표 검사 1개. Claude in Chrome은 로그인 필요 시 보조 | 사/근 |
| 판정 | 실행 증거 우선, `VERIFIED / NOT VERIFIED / INCONCLUSIVE`(보류 ≠ 통과). 평가자 입력은 diff + AC + 증거만. 같은 모델 계열 자기선호 한계 문서화 | 근 |
| 코드 그래프 | 조건부(파일 수 기준): 결정적 import 그래프, 바뀐 파일 1-hop만 조회 → 테스트 선택·영향 범위·충돌표. 전체 주입 금지. understand-anything은 자동 구간 사용 안 함(추출 스크립트만 재사용 검토) | 근 |
| Hook 신뢰성 | sh 래퍼가 `.murba/` 확인 후 node 호출(node 없어도 전 프로젝트 마비 없음), 차단 옵션은 가드에만, 이벤트별 출력 형식 준수(Stop은 최상위 `decision`), 상태 경로는 항상 프로젝트 루트 기준(worktree 대응), 상태 쓰기는 lock 또는 추가 전용 로그, 실제 payload 캡처 테스트 + 실제 실행 + 음성 대조군, 실행 기록·liveness, 비상 해제는 문서에만 | 근 |
| PR·머지 | pr-reviewer 판정을 status check로 게시. 리뷰 + 테스트 + 브라우저 증거 + SHA 일치 시 자동 squash 머지. status check는 쓰기 권한이 있으면 누구나 올릴 수 있으므로 **전용 GitHub App을 필수 체크 출처로 지정**해야 하고, private 저장소는 Pro 이상 또는 public 필요. 조건 미충족 시 PR까지만. hook·정책·eval·비가역 변경 PR, tag/Release는 사용자 | 사/근 |
| 보고 | `.murba/report.md`(첫 줄: 실패·생략 / 미검증 / 범위 밖 변경) → 스크립트로 HTML | 사 |
| 기록 | main 누적: CHANGELOG, `docs/history/`, `docs/decisions/`, `docs/evolve/`. 원본 증거는 git 제외 | 사 |
| evolve | 주 1회 클라우드 루틴(GitHub 공개 후) + 로컬 수동 실행. 입력: 자기 실행 기록(2회 이상 반복 실수) → 삭제 후보 → 외부(공식 문서·marketplace·논문). 구성요소별 "담은 가정 + 제거 실험". eval 통과 시만 PR, `evals/`·hook 수정 금지. 별도 학습 원장 없음 | 사 |
| 스킬 작성 | SKILL.md 500줄 이하, 핵심 규칙은 앞 4k 토큰 안(압축 후 5k만 복원), 20KB는 자체 규칙, description은 트리거만 | 근 |
| 외부 스킬 | 개발용: 공식 `plugin-dev@claude-plugins-official` 플러그인을 이 프로젝트 범위로 설치(hook-development, plugin-structure 포함. 원래 출처 `anthropics/claude-code`에서 스킬이 없어져 대체). 플러그인엔 라이선스(모두 MIT)·내용 검토 후 한국어 개작 + 출처: grill-me·batch-grill-me·tdd·git-guardrails(mattpocock), verification-before-completion(superpowers), review-pr(warpdotdev), writing-changelogs(riekelt) | 사 |

## 결정 과정에서 바뀐 것
| 항목 | 처음 | 최종 | 바뀐 이유 |
|---|---|---|---|
| 승인 게이트 | 완전 자동(승인 없음) | 기획서 1회 승인 후 완전 자동 | superpowers: grill 답변을 승인으로 오해한 사고 사례 |
| 10단계 | 항상 전체 | 0단계 작업 설계가 깊이·생략(사유 필수) 결정 | 사용자 요청: 시작 전 단계 설정 |
| 전문 에이전트 | 프론트·백엔드·AI·디자인 4개 에이전트 | builder 1개 + 역할 스킬 4개 | 사용자: "예시일 뿐, 필요 없으면 제거". 공식 문서: 같은 일을 서브에이전트에 넘겨도 품질 안 오름 |
| 수정 루프 | 3회 → 5라운드 | 3라운드(3라운드는 상위 모델 새 builder) | 논문: 2~3회 안에 효과 대부분 소진, 새 컨텍스트가 핵심 |
| Stop 상한 | 단계당 5회 | 단계당 3회·실행당 12회 | gstack 측정치, bkit 토큰 낭비 사례 |
| 병렬 builder | 독립 작업 적극 병렬 → 독립 산출물만 | 기본 꺼짐, eval 근거 생기면 켬 | 논문: 순차 과제 최대 −70%, Cognition 2026 |
| 비가역 처리 | ask/defer로 그 갈래 정지 | deny + 결정 큐 | 공식 문서·bkit #148: ask/defer는 무인 실행에서 멈춤 |
| 리뷰 필터 | 신뢰도 ≥80만 채택 | 실행으로 증명된 지적만 차단, 나머지 보류 기록 | pstack interrogate, superpowers "조용한 폐기 금지" |
| 학습 원장 | (제안) | 두지 않음, evolve가 실행 기록 분석 | 사용자 선택 |
| 외부 스킬 | 독립형 | 개발용 공식 플러그인 설치 + 플러그인엔 개작 | 사용자 선택 |
| 단계 순서 | 4 진행 → 5 셋팅 | 5 셋팅(오케스트레이터)을 4 테스트 작성보다 먼저 | 기획서 검토: 테스트 러너·보호 파일이 먼저 있어야 하고 builder는 쓸 수 없음. 사용자 확정(2026-11-24) |
| QA 단계 | 8 검증과 9 QA를 evaluate 하나로 | qa 단계 신설: 현재 head에서 전 AC 재판정 + 전체 회귀 + 뮤테이션 + flaky | 기획서 검토: AC별 커밋이 앞 판정을 무효로 만드는 모순 |
| PR 게이트 | hook으로 pr-reviewer만 status check 게시 | GitHub App을 출처로 지정 | 원문 대조: 쓰기 권한자는 누구나 게시 가능 |
