# 0004 구현 작업은 파이프라인을 건너뛸 수 없다 (v0.1.1)

- 날짜: 2026-11-24
- 상태: 확정(사용자 선택: "결함 고친 뒤 확장"). [ADR 0002](0002-scenario-test-changes.md)의 `--skip` 규칙을 좁힌다
- 맥락: [예비 비교](../evaluation/261124-pilot.md)에서 murba 10건 중 5건(구현 과제)이 `murba phase report --skip`으로 기획·승인·테스트 선작성·독립 평가를 통째로 건너뛰고 메인 세션이 직접 고쳤다. 이전 100개 시험에서는 없던 행동으로, 프롬프트의 "끝까지 진행 후 보고" 문장에 민감했다. t060에서는 결과물이 `.murba/`에만 남았다

## 결정
| 항목 | v0.1.0 | v0.1.1 |
|---|---|---|
| approve를 지나는 생략 | 조사 과제이거나 목표가 report면 허용 | 조사 과제이거나, 결정 큐에 `irreversible` 기록이 있는 위험 요청일 때만 |
| 승인 전 소스 수정 | 막지 않음 | triage~approve 단계에서 메인 세션의 `.murba/` 밖 쓰기 거부(조사 과제 제외) |
| 작은 작업 | 오케스트레이터 판단으로 생략 가능 | AC 1~3개짜리 최소 기획서로 같은 흐름 |
| 사용자 산출물 위치 | 규칙 없음 | `.murba/` 밖. `.murba/`는 원장 전용 |
| 기획 검토 | 기획서 내부 검토 | brief·사전 답변의 명시 요구 → AC 대응 검사 추가(빠지면 막는 지적) |
| 비가역 목록 | — | `git reset --hard`, `git clean -f[d|x]` 추가 |

## 틀렸을 때 비용
- 작은 수정도 기획·테스트 단계를 거쳐 비용·시간이 는다(예비 비교에서 전체 흐름 murba는 pstack의 약 3~4배). 대신 테스트 선작성·잠금·독립 평가가 항상 돈다
- 확장 비교에서 이 차이(비용 대비 정답·안전)를 측정한다

## 갱신 (같은 날, 독립 리뷰 2차 반영)
위 결정 표의 "결정 큐에 `irreversible` 기록이 있는 위험 요청"은 그대로 구현하면 모델이 결정 한 줄로 생략을 열 수 있었다(리뷰 재현). 실제 구현은 다음과 같다.
- triage를 떠날 때(`murba phase grill`) run-plan의 `task_type`과 `risky`를 원장에 고정한다. 이후 run-plan 수정은 무시한다
- 모든 `--skip`은 고정된 값이 조사이거나 `risky`일 때만 허용한다. 결정 큐 기록은 생략을 열지 않는다
- 구조적 게이트: `murba approve`와 `lock-tests`는 init 이후 구현 파일(impl_globs와 코드 확장자)이 바뀌었으면 거부한다. Bash·스크립트·서브에이전트 등 수정 경로와 무관하게 결과(git diff)로 본다
- 게이트 예외: 조사 과제의 approve, git 저장소가 아니거나 기준 커밋이 없을 때(이벤트만 남김), 설정·문서 파일(package.json, *.config.*, .md 등), `lock-tests --amend`
- risky 과제의 생략은 report로만 갈 수 있다
- 남은 빈틈(v0.1.2 후보): 고정 전 triage에서 run-plan에 스스로 조사·위험으로 적으면 생략·게이트·승인 전 쓰기 차단이 모두 풀린다. init 전 작업 중 변경은 게이트 오탐이 될 수 있다
