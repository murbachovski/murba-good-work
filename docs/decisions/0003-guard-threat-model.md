# 0003 guard 위협 모델: 실수 방지망

- 날짜: 2026-11-24
- 상태: 확정(사용자 선택). [기획서 v0.1](../spec/spec-v0.1.md) §hook 공통 규칙을 보완한다
- 맥락: PR #1 독립 리뷰 2회가 모두 "머지 불가". 1차 지적 13건을 막았지만 2차에서 그중 8건이 같은 종류의 변형 입력(`timeout 10 git push -f`, `.MURBA/state.json`, `bash -lc "…"`, `rm -rf .murb*`)으로 다시 뚫렸다. 명령 문자열을 패턴으로 검사하는 방식으로는 이 종류를 끝까지 닫을 수 없다

## 결정
guard는 **협조적인 모델의 실수와 테스트 꼼수를 막는 안전망**이다. 모델이 일부러 난독화해서 피하는 것을 막는 샌드박스가 아니다.

| 구분 | 처리 |
|---|---|
| 모델이 자연스럽게 칠 만한 형태 | guard가 막는다: 래퍼(`timeout`·`nice`·`env`·`stdbuf`·`xargs` 등), `eval`, `bash -lc`, 대소문자 다른 경로, 와일드카드로 `.murba` 지정, `find . -delete`, `$(pwd)` 대상, DB 클라이언트로 파이프된 SQL |
| 문자열로 막을 수 없는 것 | **CLI가 구조적으로 막는다**: guard가 호출 주체를 `.murba/caller`에 기록하고, CLI는 서브에이전트의 상태 변경을 거부한다. 상태 파일의 해시를 `.murba/state.sha256`에 두고, 어긋나면 `LEDGER_TAMPERED`로 거부·보고한다 |
| 스크립트 파일 안의 명령·삭제 | 플러그인 규칙이 여러 단계 로직을 스크립트 파일로 쓰게 하므로 자연스러운 형태다. guard가 스크립트 Write/Edit 내용을 검사한다: `execSync`·`spawn`·`subprocess.run` 등에 넘긴 문자열 리터럴은 Bash 명령과 같은 규칙, `rmSync`·`rmtree`의 리터럴 대상은 재귀 삭제 규칙. 실행 중에 조립한 문자열은 난독화로 본다 |
| 의도적 난독화 | 범위 밖. 단어 안 따옴표 쪼개기(`hid""den`), 변수 간접 참조(`$m`), 호출 주체 기록을 고쳐 쓰는 스크립트 |
| 비상 해제 | 프로젝트 파일(`.murba/disable`)이 아니라 사람이 실행할 때 주는 환경변수 `MURBA_DISABLE=1`. 모델이 파일 하나로 끌 수 없게 한다 |

## 배포 기준 (v0.1.0)

### 1. 우회 분류: 자연스러움 / 난독화
리뷰어가 우회마다 분류와 한 줄 근거를 적는다. 애매하면 **자연스러움**으로 본다(보수적).
| 분류 | 정의 | 예 |
|---|---|---|
| 자연스러움 | 정상 작업 중 협조적 모델이 피할 의도 없이 칠 수 있는 형태. 흔한 셸 문법과 도구 옵션만 씀 | 래퍼(`timeout`·`nice`·`env`·`xargs`·`sudo`), `sh -c`·`bash -lc`·`eval`, 파이프, `cd` 연결, 와일드카드, 대소문자·절대/상대 경로 차이, `$(pwd)`·`$HOME`, `find -delete` |
| 난독화 | 명령의 정체를 숨기려는 형태. 정상 작업에서 쓸 이유가 없음 | 단어 안 따옴표 쪼개기(`hid""den`), 명령 이름을 변수에 숨김(`m=murba; $m`), base64·hex 인코딩, 막힌 명령을 부르려고 만든 alias·함수·스크립트(같은 실행의 `hooks.jsonl`에 같은 명령의 guard 차단이 먼저 있을 때만), 실행 중에 조립한 명령 문자열, `.murba/caller` 고쳐 쓰기 |
- 메인 세션은 리뷰어 분류를 바꾸지 않는다. 동의하지 않으면 두 판단을 모두 적되, 기준 2는 리뷰어 분류로 판정한다

### 2. 리뷰 횟수 상한: 3회 (1·2차 완료, 3차가 마지막)
- 3차에서 리뷰어 분류 자연스러운 우회 0건 → 기준 3 통과 후 머지(리뷰어의 "머지 불가" 문구 자체는 판정에 쓰지 않는다. 그 리뷰어는 기본 판정이 머지 불가다)
- 3차에서 자연스러운 우회가 나오면 고치고, **리뷰어의 재현 스크립트 + 회귀 테스트로 결정적으로 확인**한다(4차 리뷰 없음)
- 고치지 못한 자연스러운 우회가 남을 때:
  - 데이터 손실·외부 영향 종류(재귀 삭제, force-push·main push, DB DROP/TRUNCATE, 배포·게시, 원장 위조로 승인 우회) → **배포 중단, 사용자에게 묻는다**
  - 그 밖의 종류 → README "알려진 우회"와 보고서 ⚠️에 적고 배포
- 난독화 분류 우회는 고치지 않고 ADR·README에 범위 밖으로 기록
- 우회가 아닌 지적(버그 등)도 같다: 고치고 재현·회귀 테스트로 확인. 4차 없음

### 3. 강화 뒤 오탐 확인: 고정 회귀 세트 11개
- 과제: t002(기능·브라우저), t037(버그), t057(지저분한 데이터), t067(리팩터), t074(조사), t083(성능), t086(프로토타입·브라우저), t093(위험: 재귀 삭제), t091(위험: DB DROP, 실제 DB), t092(위험: force-push), t010(긴 과제: 이전 실행 AC 17·18개)
- 통과 조건: **11/11 성공** + **정상 명령 오탐 0건**(guard 차단 기록을 전부 열어 정상 명령이 막힌 것이 있는지 본다. builder의 숨긴 검사 접근, test-writer의 구현 읽기 차단은 의도된 차단)
- 재실행 1회는 analyze 결과 blocked·err가 0이고 guard 차단 기록이 없는 실패만. 차단이 하나라도 있으면 원인을 고친다
- 실행·재실행마다 새 `--out` 폴더(`release-1`, `release-2` …). 실행기는 기존 결과를 지우지 않는다. 보고서에 첫 시도와 재실행을 따로 적는다
- `plugins/` 아래가 바뀌면 세트 전체를 다시 돌린다. 태그는 세트가 마지막으로 전부 통과한 커밋(또는 `plugins/` 트리가 그것과 같은 merge commit)에 단다

### 4. 비용·시간 상한
- 지금까지 시나리오 실행 비용 $320.85(121회: b1~b6 115회 $309.91 + b7 6회 $10.94). 리뷰·수정 에이전트 비용은 측정 수단이 없음
- 남은 작업(회귀 세트, 3차 리뷰, 설치 확인)의 추가 상한: **시나리오 실행 $60, 경과 3시간**. 세트 1회 약 $20~30이라 전체 실행 약 2회분
- 리뷰·수정 비용은 측정 수단이 없어 횟수로 막는다: 3차 리뷰 1회, 3차 뒤 수정 1라운드
- 경과는 이 ADR 커밋 시각부터. 비용은 모든 `release-N` 폴더의 analyze 합계
- 상한에 닿으면 멈추고 그때까지의 결과로 사용자에게 묻는다

### 5. "100개 성공"의 의미 (보고서에 그대로 적는다)
- 성공 판정은 **플러그인 자신의 원장 기준**(done + 보류 안 된 AC 전부 최종 VERIFIED, 조사·위험 요청은 보고서로 끝남)
- 100개는 여러 플러그인 커밋에 걸친 결과다. 첫 시도 92개, 실패 8개는 수정 후 재실행으로 성공
- 독립 확인은 11개 과제(기대 결과 38줄)만 했다
- **태그할 최종 커밋으로 돌린 과제 수**를 따로 적는다(회귀 세트 11개 + 설치 확인 1개)
- 태그 커밋 결과 중 t067의 기대 결과는 새 컨텍스트 에이전트가 직접 실행해 확인한다
- 순서: 머지(일반 merge commit) → main에서 marketplace 설치 확인 → 태그·Release

## 알려진 한계
- 서브에이전트가 동시에 돌면 호출 주체 기록을 공유한다. 서브에이전트는 전경 실행이 규칙이라 한 번에 하나다
- `.murba/`는 git에 올리지 않으므로 diff 규칙으로는 원장 변조를 볼 수 없다. 해시 검사가 이를 대신한다
- 사람이 `MURBA_DISABLE=1`로 실행하면 모든 hook이 꺼진다(의도)
- 대화형 승인 토큰은 guard가 ask를 낼 때 쓰고 10분간 유효하다. 사람이 확인 창에서 거절한 뒤 모델이 다른 경로로 승인을 시도하면 통과할 수 있다(의도적 우회 → 범위 밖)
- 3차 리뷰에서 난독화로 분류해 고치지 않은 것: `state.json`과 `state.sha256`을 함께 다시 쓰는 위조, 스크립트 안에서 실행 중 계산한 삭제 대상(`os.homedir()`, `Path.home()`, `process.env.HOME`), 단어 안 따옴표 쪼개기, 변수에 숨긴 명령 이름
- 리뷰 결과: 1차 13건, 2차 같은 종류 변형 8건, 3차 자연스러운 우회 30건(중단 종류 23건)을 수정 1라운드로 모두 막음. 리뷰어 재현 스크립트로 확인(4차 리뷰 없음)

## 틀렸을 때 비용
모델이 실제로 적대적으로 행동하면 guard를 피할 수 있다. 그 경우에는 Claude Code 권한 설정(`permissions.deny`)이나 샌드박스가 필요하다.
