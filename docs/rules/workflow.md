# 작업 규칙

이 저장소에서 작업할 때 지키는 규칙. 사용자 전역 지침(`~/.claude/CLAUDE.md`)이 우선한다.

## 1. 시작 전
- 작업을 확인 가능한 목표로 바꾼다. 여러 단계면 `단계 → 확인` 계획을 먼저 짧게 적는다
- 기획서(`docs/spec/`)와 결정 기록(`docs/decisions/`)에서 관련 절을 읽는다
- 해석이 여럿이면 고르지 말고 선택형으로 묻는다

## 2. 질문
- 질문은 **항상 선택형(AskUserQuestion)**. 텍스트 질문 금지. 추천안은 첫 번째에 `(Recommended)`
- 질문은 한 번에 모아서 한다(최대 4개). 다른 질문의 답에 달린 질문은 다음 라운드로
- 사실(파일·문서·도구로 확인 가능한 것)은 묻지 않고 직접 확인한다

## 3. 막히지 않게 진행하기 (결정 큐)
작업 중 결정이 필요하면 아래로 분류한다.

| 분류 | 예 | 처리 |
|---|---|---|
| 기계적 | 변수명, 파일 위치, 형식 | 그냥 결정 |
| 취향 | 라이브러리 선택, 구조안 | 추천안으로 진행 + 결정 큐에 기록 + 영향 파일 표시 |
| 사용자 방향 변경 | 사용자가 정한 것을 뒤집는 결정 | 자동 결정 금지. 결정 큐에 올리고 다른 작업 계속 |
| 비가역 | 삭제, 배포, 마이그레이션, 비밀키, 결제, 외부 게시, push | **그 작업만 멈춤**, 결정 큐에 올리고 나머지 계속 |

- 결정 큐는 단계 경계나 최종 보고에서 한 번에 선택형으로 묻는다
- 최종 보고에 "내가 내린 결정과 틀렸을 때 비용"을 빠짐없이 적는다

## 4. 완료 주장
- "됐다", "통과"는 **이번에 직접 실행한** 명령, 출력, 종료 코드가 있을 때만
- 서브에이전트의 "통과" 보고는 다시 실행해 확인한다
- 확인 못 한 것은 "미검증"으로, 건너뛴 것은 "생략(사유)"로 보고한다

## 5. 범위
- 시키지 않은 것은 하지 않는다. 필요해 보이면 먼저 묻는다
- 요청과 관계없는 주변 문장·코드·형식을 고치지 않는다
- 바꾼 모든 줄은 요청으로 거슬러 올라가야 한다

## 6. git
- 이 저장소: 커밋·push는 **사용자 지시 때만**. 지시 시 `feat/*` 등 브랜치에서 작업하고 PR
- 플러그인이 대상 프로젝트에서 실행될 때의 커밋 규칙은 기획서를 따른다(`feat/*`에 작업별 자동 커밋, main 직접 금지)
- GitHub 계정은 사용자 전역 지침이 허용한 계정만 쓴다. 다른 계정이 잡히면 작업하지 말고 알린다

## 7. 독립 검토
- 기획서·중요 문서·PR은 새 컨텍스트 독립 에이전트로 검토한다
- 검토 요청에는 결론을 주지 말고 대상 파일만 준다
- 실행이나 문서로 증명된 지적만 반영 대상으로 본다. 나머지는 `보류`로 기록하고 버리지 않는다
