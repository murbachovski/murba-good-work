내가 내린 결정

결정틀렸을 때 비용
셸 해석은 BSD·GNU 중 더 많이 막는 쪽을 택함(맨 앞 ''는 -n이 있거나 다른 파일이 없으면 GNU 해석도 봄)sed -i '' -n 's#<보호 경로>#…#p' <파일>은 오탐
점 없는 BSD 접미어(sed -i bak …)는 그대로 둠그 형태에서 스크립트에 보호 경로가 있으면 오탐(main도 같음)
둘 다 오류로 끝나는 형태(sed -i .bak F)는 허용으로 바뀌어도 받아들임sed 구현이 문서와 다르면 놓침(리뷰어가 BSD 실행으로 확인)
t010 시간 초과를 sed 변경과 무관한 것으로 판단0.1.4 역할 강제가 test-write 단계를 늘리는 마찰은 남음(관찰로 기록)

관찰(다음 후보)

  • 0.1.4 역할 강제의 마찰: setup에서 만든 보조 파일이 잠금 게이트에 걸리면 test-write 단계에서 메인 세션이 러너 설정을 못 고쳐 test-writer를 다시 불러야 한다. 시나리오 실행 3번 중 1번 시간 초과에 영향
