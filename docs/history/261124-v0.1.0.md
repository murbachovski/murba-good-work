## 시험 방법
- 과제 100개(`scenarios/tasks.json`): 기능 35, 버그 20, 리팩터 8, 조사 7, 성능 5, 프로토타입 5, 지저분한 데이터 10, 위험 요청(삭제·비밀) 6, 모호·충돌 요구 4. 시드 프로젝트 28개
- 과제마다 임시 git 저장소 → `MURBA_HEADLESS=1 claude -p "/murba-good-work:run <brief>"`, 서브에이전트도 sonnet 강제, 사전 답변 제공
- 성공 = 마지막 단계 done + 보고서 있음 + 보류 안 된 모든 AC 최종 VERIFIED(조사·위험 요청은 보고서로 끝나면 성공)
- 배치마다 실패 원인 분석 → 수정 → 테스트 → 커밋 → 다음 배치

## 시험에서 고친 것 (상세: [ADR 0002](../decisions/0002-scenario-test-changes.md))
| 문제 | 수정 |
|---|---|
| 무인 실행이 승인에서 멈춤 | `MURBA_HEADLESS=1`이면 자동 승인 |
| guard가 따옴표 안 `>`를 쓰기로 오인 | 따옴표 가리고 리디렉션 파싱 |
| AC마다 LLM 평가 → 느리고 흔들림 | AC별 판정은 테스트 종료 코드, 독립 평가자는 qa·browser 1회 |
| 조사·위험 요청이 질문으로 끝남 | `--skip` 생략 기록, headless 질문 종료 차단 |
| AC 의존 때문에 보류 남발 | `[after:AC-x]` 순서, 자동 해제 |
| 복합 Bash 명령 권한 거부 | 단순 명령 규칙, 스크립트 파일, `murba evidence-run` |
| `-p`가 10분 뒤 서브에이전트 강제 종료 | 서브에이전트 전경 실행 |
| qa에서 찾은 결함을 못 고치고 끝남 | `murba phase fix --ac <ID>` |
| 성능 AC가 측정 노이즈로 실패 | 5회 이상 중앙값 |
| 무인 실행마다 settings 쓰기 시도 → 거부 | headless에서는 허용목록 생략 |

## 내가 내린 결정 (틀렸을 때 비용)
- AC별 판정을 LLM 대신 테스트 종료 코드로: 테스트가 약하면 거짓 통과 → qa 뮤테이션 검사·독립 평가로 보완
