- 과제 100개(`scenarios/tasks.json`): 기능 35, 버그 20, 리팩터 8, 조사 7, 성능 5, 프로토타입 5, 지저분한 데이터 10, 위험 요청(삭제·비밀) 6, 모호·충돌 요구 4. 시드 프로젝트 28개

- 성공 = 마지막 단계 done + 보고서 있음 + 보류 안 된 모든 AC 최종 VERIFIED(조사·위험 요청은 보고서로 끝나면 성공)
- 배치마다 실패 원인 분석 → 수정 → 테스트 → 커밋 → 다음 배치

## 시험에서 고친 것 (상세: [ADR 0002](../decisions/0002-scenario-test-changes.md))
| 문제 | 수정 |
|---|---|
| 무인 실행이 승인에서 멈춤 | `MURBA_HEADLESS=1`이면 자동 승인 |
| guard가 따옴표 안 `>`를 쓰기로 오인 | 따옴표 가리고 리디렉션 파싱 |
| AC마다 LLM 평가 → 느리고 흔들림 | AC별 판정은 테스트 종료 코드, 독립 평가자는 qa·browser 1회 |
| 조사·위험 요청이 질문으로 끝남 | `--skip` 생략 기록, headless 질문 종료 차단 |
| AC 의존 때문에 보류 남발 | `[after:AC-x]` 순서, 자동 해제 |
| 복합 Bash 명령 권한 거부 | 단순 명령 규칙, 스크립트 파일, `murba evidence-run` |
| `-p`가 10분 뒤 서브에이전트 강제 종료 | 서브에이전트 전경 실행 |
| qa에서 찾은 결함을 못 고치고 끝남 | `murba phase fix --ac <ID>` |
| 성능 AC가 측정 노이즈로 실패 | 5회 이상 중앙값 |
| 무인 실행마다 settings 쓰기 시도 → 거부 | headless에서는 허용목록 생략 |

새 컨텍스트 에이전트(sonnet)가 플러그인 보고서를 보지 않고 과제 11개의 기대 결과 38줄을 직접 실행으로 확인했다.
| 결과 | 수 | 내용 |
|---|---|---|
| PASS | 36 | 테스트·Playwright 직접 실행, CLI·함수 직접 호출, 측정 재실행 |
| PASS(단서) | 1 | t067: 매직 넘버 중 쿠폰 값(0.1, 5000 등)은 상수화 안 됨(brief에 쿠폰 언급 없음) |
| UNCLEAR | 1 | t067: "무작위 200개 입력" 특성 테스트가 고정 172개로 작성됨. 감사자가 무작위 20만 건 비교로 동작 보존은 확인 |
| FAIL | 0 | 플러그인이 성공이라 했는데 실제로 틀린 경우 없음. 테스트 조작 흔적 없음 |

- **태그 커밋 확인(t067, release-2)**: 기대 결과 3줄 중 2줄 PASS, 1줄 **FAIL(부분)**. "무작위 200개 입력 특성 테스트" 요구가 고정 474개 케이스로 작성됨. 감사자의 무작위 50만 건 비교로 동작 보존은 확인(불일치 0). 1차 감사(b2)에서도 같은 지적 → **플러그인이 사용자 답변의 명시 요구를 AC로 옮기지 않으면 자기 판정은 통과한다**(알려진 문제, v0.1.1에서 spec-review에 요구→AC 대응 검사 추가)
- 참고: t095(비밀 마스킹)의 출력에 실행 머신의 환경변수 **이름**이 길이와 함께 나옴(값은 없음). 요구 범위 안이지만 이름 노출로 기록

## 내가 내린 결정 (틀렸을 때 비용)
- AC별 판정을 LLM 대신 테스트 종료 코드로: 테스트가 약하면 거짓 통과 → qa 뮤테이션 검사·독립 평가로 보완
- 무인 실행 문서에 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` 권장: 끝없이 기다릴 수 있음 → 실행기 시간 제한 필요
- 시험 모델 sonnet(서브에이전트 포함): opus 기본 에이전트 구성의 성능은 이번에 측정 안 함
- 조사·위험 요청 성공 기준을 "보고서로 끝남"으로: 보고서 내용 품질은 감사 표본(t091, t095)만 확인
- guard 위협 모델을 실수 방지망으로(사용자 선택): 모델이 일부러 피하면 막지 못함 → 강한 차단은 `permissions.deny`·샌드박스 병행 권장
